FINDINGS (9 runs, 180 total iterations)

1. CANONICALIZATION TEST
   Block insertion order (A-B-C, C-B-A, B-A-C):
     All three orders produce identical 8,753-byte output: PASS

   Field order within records:
     CAVEAT: Test passes only because Python dicts (3.7+) preserve insertion order.

     FINDING: dumps_canonical does not sort fields alphabetically; it preserves
       the Document field order from the parser. Different input field orders
       produce different output.

     LATENT PARITY BUG: A Rust HashMap or Go map port would emit fields in
       iteration order, causing byte-identity to fail on first cross-language run.

     RECOMMENDATION: Sort fields alphabetically because implementation-order
       independence is the whole point of canonical form. This is necessary for
       content-addressed use, but more fundamentally: canonical output must be
       byte-identical across all implementations regardless of their iteration
       order semantics.

     TRADEOFF: Canonical form will lose readable column ordering (which is a
       stated ISON design goal). This is acceptable since canonical output is
       for machines, but dumps_canonical should be documented as visibly
       different from dumps.

   Byte ratio: 2.90x (JSON vs ISON), 65.5% reduction
   Token ratio: 2.35x (separately measured on synthetic 350-record data),
     57.4% reduction
   NOTE: Byte ratio ≠ token ratio due to JSON's punctuation overhead
     (JSON: 3.32 chars/token vs ISON: 3.65 chars/token)

   CAVEAT: Token measurement is from separate synthetic test, not from actual
   benchmark outputs. Should measure tiktoken over real 8,753/25,401-byte
   outputs before quoting as definitive number.

5. TIMING METHODOLOGY
   This benchmark measures serialization only (data generation excluded).
   Prior benchmark (100619) included from_dict in timed region:
     110.08ms total for 100 iterations ≈ 1.1ms/iter (parsing + serialization)
   This benchmark:
     0.988ms/iter median (serialization only, document pre-generated)
   Change: Isolated serialization from parsing to measure format overhead only.
   Prior results with combined timing are NOT comparable; they measured a
   different quantity (full parse cycle vs serialization pass).
